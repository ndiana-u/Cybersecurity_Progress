LAB NAME:  SQL injection UNION attack, retrieving multiple values in a single column

DESCRIPTION
This lab contains a SQL injection vulnerability in the product category filter. The results from the query are returned in the application's 
response so you can use a UNION attack to retrieve data from other tables.

The database contains a different table called users, with columns called username and password.

To solve the lab, perform a SQL injection UNION attack that retrieves all usernames and passwords, and use the information to log in as the 
administrator user.

DIFFICULTY LEVEL: Practitioner

LAB LINK: https://portswigger.net/web-security/sql-injection/union-attacks/lab-retrieve-multiple-values-in-single-column

STEPS I USED TO SOLVE THIS LAB
- I clicked on the category 'accessories' and intercepted the request. Then I sent the request to Burp repeater so I could manipulate that 
request multiple times. 
- In Burp repeater, I used 'ORDER BY 1--' to get the number of columns available. I added it to the category filter as seen below:
GET /filter?category=Accessories'+ORDER+BY+1--
I kept incrementing the number by 1 and when I got to 3, I got an error which means that there are only 2 columns available. 
- I tried '+UNION+SELECT+'a',NULL-- to check if the first column accepted string data but I got an error.
- I tried '+UNION+SELECT+NULL,'a'-- and the request was successful. So i knew the second column accepted string data.
- Only one column accepted string data and I needed to get 2 columns of information(i.e username and password). So I concatenated the values
together in my payload and used '~' to demarcate them. The payload I used is below:
'+UNION+SELECT+NULL,username+||+'~'+||+password+FROM+users--
