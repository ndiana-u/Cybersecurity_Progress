GIT BRANCH 
A Git branch is like a separate line of development in your project. It allows you to work on different features, fixes, or experiments without affecting the main codebase.
Key Points About Git Branches:
- Separate Workspaces: Each branch has its own set of changes, so you can work on multiple things at once without interfering with each other.
- Main Branch: Usually, there’s a main branch (commonly called master or main) where stable code lives. You can create other branches for new features or fixes.

### **GIT BRANCHES EXPLAINED**  

A **Git branch** is like a **separate workspace** where you can develop new features, fix bugs, or experiment **without affecting the main project**. Think of it as creating a **copy of your project**, where you can make changes independently.  

---

### **Key Points About Git Branches**  

🔹 **Isolated Development:** Each branch **works independently**, so changes made in one branch **do not** affect other branches until merged.  

🔹 **Main Branch (Stable Code):**  
   - The **main** branch (sometimes called `master` or `main`) holds the **stable, production-ready code**.  
   - New features, bug fixes, or updates are usually developed on **separate branches** before merging them back into the main branch.  

🔹 **Why Use Branches?**  
   - Prevents breaking the main codebase.  
   - Allows multiple developers to work on different features at the same time.  
   - Makes it easy to experiment and discard changes if needed.
